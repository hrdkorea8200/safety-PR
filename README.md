# 한국산업인력공단 홍보미디어실 · 안전·친환경 지킴이 / 안전신문고 (GitHub Pages 버전)

QR코드로 누구나 접속해 안전수칙을 보고, 사진과 함께 안전신문고에 제보할 수 있습니다.
**촬영현장 안전가이드(촬영장비 9종 안전 수칙·현장 공통 수칙·장비별 QR 라벨)도 같은 사이트의 "촬영안전" 탭으로 들어 있습니다.**
접수된 제보와 사진은 **관리자만** 숫자 암호로 확인·처리하고, 접수증을 출력할 수 있습니다.

## 어떻게 동작하나요

| 역할 | 담당 | 비용 |
|---|---|---|
| 화면(HTML) 공개 | **GitHub Pages** | 무료 |
| 제보·사진 저장, 관리자 로그인 | **Supabase** | 무료 플랜 |

GitHub Pages는 화면만 보여 주는 곳이라 제보를 저장할 수 없습니다. 그래서 저장은 Supabase가 맡습니다.
**누구나 제보를 "넣을 수만" 있고 "읽을 수는 없으며", 읽기·처리·삭제는 관리자 계정만 가능**하도록 Supabase 쪽에 규칙이 걸려 있습니다(`supabase/schema.sql`).

```

admin.html        관리자 페이지 (바로가기 화면 맨 아래 "관리자" 버튼)
```

## 설치 순서 (처음 한 번, 약 30분)

### 1단계. Supabase 가입 · 프로젝트 만들기
1. https://supabase.com 에서 가입(GitHub 계정으로 로그인 가능)
2. **New project** → 이름 `safety-site`, 데이터베이스 비밀번호(따로 보관), **Region: Northeast Asia (Seoul)** 선택 → Create
3. 프로젝트가 준비될 때까지 1~2분 기다립니다.

### 2단계. 데이터베이스 설정 (SQL 실행)
1. 왼쪽 메뉴 **SQL Editor → New query**
2. `supabase/schema.sql` 파일 내용을 **전부 복사해 붙여넣고 Run**
3. `Success. No rows returned` 가 나오면 완료입니다. (여러 번 실행해도 안전합니다)

> **기능 추가 SQL (필수)**: 위 `schema.sql` 실행 뒤에 `supabase/add_features.sql` 도 같은 방법으로 붙여넣고 **Run** 하세요. 접수번호 조회, 처리 결과 공개, 이달의 캠페인, 사진 정리 표시에 필요하며, 기존 데이터에는 영향이 없고 여러 번 실행해도 안전합니다.

### 3단계. 관리자 계정 만들기
1. 왼쪽 메뉴 **Authentication → Users → Add user → Create new user**
   - Email: 관리자 이메일 (예: `safety-admin@회사도메인`) — 실제 메일이 아니어도 됩니다
   - Password: **숫자 암호 + `-safety`**  (예: 암호를 `8195`로 쓰려면 `8195-safety`)
   - **Auto Confirm User** 체크 → Create user
2. **SQL Editor → New query** 에 `supabase/add_admin.sql` 내용을 붙여넣고, 맨 위 `admin@example.com` 을 **방금 만든 이메일**로 바꾼 뒤 Run
   → 결과에 이메일이 한 줄 나오면 관리자 등록 성공입니다.
3. 권장: **Authentication → Sign In / Providers**(또는 Settings)에서 **Allow new users to sign up(회원가입 허용)을 끕니다.** 관리자 외 계정이 생기지 않게 하기 위함입니다.

> ⚠ **숫자 암호 길이에 대해**: 이 구조는 별도 서버가 없어 "N회 틀리면 잠금" 기능이 없습니다(Supabase의 시도 횟수 제한만 적용).
> 숫자 4자리(예: 8195)는 경우의 수가 1만 개뿐이라 시간을 들이면 맞힐 수 있습니다. **8자리 이상을 권장**합니다.
> 더 안전하게 쓰려면 `site.config.js`의 `ADMIN_LOGIN_MODE`를 `'password'`로 바꿔 이메일 + 긴 비밀번호로 로그인하세요.

### 4단계. 연결 값 복사해서 설정 파일에 넣기
1. Supabase 왼쪽 아래 **Project Settings → API**(또는 Data API)에서 두 값을 복사
   - **Project URL** (`https://xxxx.supabase.co`)
   - **공개 키**: `sb_publishable_…`(새 방식) 또는 `anon public`(eyJ…로 시작, 예전 방식) 중 보이는 것. `secret`/`service_role` 키는 절대 아님
2. `site.config.js` 맨 위에서 아래 4개를 바꿉니다.
   ```js
   SUPABASE_URL: 'https://xxxx.supabase.co',
   SUPABASE_ANON_KEY: '복사한 anon public 키',
   ADMIN_EMAIL: '3단계에서 만든 이메일',
   ADMIN_PIN_SUFFIX: '-safety',    // 3단계 비밀번호 뒤에 붙인 글자와 같아야 합니다
   ```
3. ⚠ **`service_role` 키는 절대 넣지 마세요.** anon 키만 공개해도 되도록 설계돼 있습니다.

### 5단계. GitHub에 올려서 공개하기
1. https://github.com 가입 → **New repository** → 이름 예: `safety-site`, **Public** 선택 → Create
   (무료 GitHub Pages는 Public 저장소에서만 쓸 수 있습니다. 코드에는 비밀 값이 없습니다.)
2. 저장소 화면에서 **uploading an existing file** (또는 Add file → Upload files)
3. 이 폴더 안의 **모든 파일과 폴더**(`.nojekyll`, `.github` 포함)를 끌어다 놓고 **Commit changes**
   - `.github` 폴더가 올라가지 않으면 6단계(선택)는 나중에 직접 만들면 됩니다.
4. **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**
5. 1~3분 뒤 같은 화면 위쪽에 주소가 나타납니다.
   `https://내계정.github.io/safety-site/`  ← 이것이 사이트 주소입니다.

### 6단계. (권장) DB 자동 일시정지 방지
Supabase 무료 프로젝트는 일정 기간 사용이 없으면 자동 일시정지될 수 있어, 제보가 뜸한 사이트는 어느 날 접수가 안 될 수 있습니다.
1. GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - `SUPABASE_URL` = Project URL, `SUPABASE_ANON_KEY` = anon 키
2. **Actions** 탭에서 `Supabase keep-alive` → **Run workflow** 로 한 번 실행해 초록색 체크가 뜨는지 확인합니다. 이후 3일마다 자동 실행됩니다.
   (GitHub는 장기간 활동이 없는 저장소의 예약 실행을 멈출 수 있으니, 가끔 Actions 탭을 확인하세요.)

### 7단계. (권장) 사진 30일 자동 정리
저장 공간이 사진으로 가득 차지 않도록 접수 후 30일이 지난 사진을 매일 자동으로 지웁니다. 시크릿 4개 등록과 시험 실행 방법은 아래 **"사진 30일 자동 정리"** 를 보세요.

## 홈 화면 구성 · 오늘의 안전 날씨 · 안전·환경 서비스 바로가기
- **맨 위: 검색 바** → **오늘의 안전 날씨** — "오늘은 맑음 / 흐림 / 위험 단계"와 날씨 아이콘, 그 아래 **오늘의 안전 한마디**(56개가 매일 순환), 오른쪽에 안전제일 캐릭터가 표시됩니다.
- **그 아래: 공지사항**(캐릭터 포함, 안전·환경 소식) — 서비스 바로가기보다 위에 있습니다.
- **그 아래: 안전·환경 서비스 바로가기** 6칸 — 안전정보 / 안전신문고 / 비상대응 / 촬영현장 안전가이드 / 친환경 / 긴급상황 119(누르면 전화). 같은 6칸이 하단 "바로가기" 화면에도 있습니다.
- **그 아래: 이달의 안전·친환경 캠페인 카드 → 오늘의 안전·친환경 퀴즈 카드**
- **그 아래**: 아차사고 설명 → 사무실 안전 핵심 수칙 10.
- 화면 위쪽 오른쪽에는 🔍 전체 검색, "가" 화면 설정(글자 크기·고대비), 밝기 전환 버튼이 있습니다.
- **단계 선택(관리자)**: 관리자 화면 위쪽 **🌤 안전 날씨** 버튼 → 맑음/흐림/위험 선택 → 미리보기 확인 → **저장**. 저장 즉시 이용자 홈 화면에 반영됩니다.
- 단계는 **관리자가 바꿀 때까지 유지**됩니다(날마다 자동으로 바뀌지 않음). 카드의 "오늘 설정 / 2026.10.06 설정" 표시로 언제 정한 단계인지 알 수 있으니, 매일 아침 확인·갱신하는 운영 규칙을 권장합니다.
- 서버에서 단계를 읽지 못하면 "맑음"이라고 단정하지 않고 **"확인 불가"**로 표시합니다.

> **이미 설치(2단계)를 마친 경우**: 안전 날씨 저장소를 한 번만 추가하면 됩니다.
> Supabase **SQL Editor → New query** 에 `supabase/add_weather.sql` 전체를 붙여넣고 **Run**. (기존 제보·사진·공지에는 영향이 없고, 여러 번 실행해도 안전합니다.)
> 새로 설치하는 경우에는 `schema.sql`에 이미 포함되어 있습니다.
> 이 SQL을 실행하기 전에는 홈 화면 맨 위에 "확인 불가"가 표시되고, 관리자 화면에서 단계를 저장할 수 없습니다.

## 앱처럼 쓰기 (홈 화면에 추가) · 화면 디자인
- **설치**: 휴대폰에서 사이트를 열고 안드로이드는 **바로가기 → 앱처럼 설치하기 → 홈 화면에 추가**(또는 크롬 메뉴 ⋮ → 앱 설치), 아이폰은 사파리 아래 **공유(□↑) → 홈 화면에 추가**를 누르면 앱 아이콘이 생깁니다. 주소창 없이 전체 화면으로 열립니다. (HTTPS인 GitHub Pages 주소에서만 설치됩니다)
- **오프라인**: 한 번 열어 본 기기에서는 인터넷이 불안정해도 안전수칙·비상대응·촬영안전·친환경·퀴즈가 열립니다. 제보 접수·접수번호 조회·공지·안전 날씨는 인터넷이 필요합니다. 인터넷이 되면 항상 최신 파일을 먼저 불러오므로, 파일을 고쳐 올리면 바로 반영됩니다. 관리자 화면(admin)은 저장하지 않습니다.
- **앱 바·뒤로 가기**: 안쪽 화면에는 왼쪽 위 ‹ 버튼이 생기고, 스크롤하면 위쪽에 현재 화면 제목이 나타납니다. 휴대폰의 뒤로 가기 버튼도 이전 화면으로 돌아갑니다.
- **디자인 규칙**(`ui.css`): 메뉴 색은 안전보건표지의 뜻을 따릅니다(파랑=지시, 노랑=경고, 빨강=소방·긴급, 녹색=안내). 큰 제목은 간판체(Black Han Sans), 본문은 Noto Sans KR이며, 홈의 "오늘의 안전 날씨"에만 공사장 경고줄을 썼습니다. 색은 `ui.css` 맨 위 `--t-blue` 등 변수에서 바꿉니다.
- 아이콘·이름: `manifest.webmanifest`의 `name`·`short_name`, `icon-*.png`를 바꾸면 설치되는 앱 이름과 아이콘이 바뀝니다. 파일을 고치고 나서 사이트 폴더의 `sw.js` 맨 위 `VERSION` 숫자를 바꿔 올리면 모든 기기에서 저장본이 새로 만들어집니다.

## 접수번호로 처리 결과 조회 (제보자용)
- **안전신문고** 화면 위쪽 "🔎 접수번호로 처리 결과 조회"에 접수번호(예: `SF-261008-AB12C`)를 넣으면 처리 상태(접수 → 검토중 → 조치완료)와 **공개 처리 결과**가 나옵니다. 익명 제보도 조회할 수 있고, 제보 완료 화면에서 접수번호 복사·조회 버튼을 바로 쓸 수 있습니다.
- 관리자는 제보 상세에서 **"처리 결과 (제보자에게 공개)"** 칸에 안내 문구를 씁니다. 바로 아래 **"조치 내용 (관리자 메모 · 내부용)"** 은 공개되지 않습니다. 공개 문구에는 이름·연락처 같은 개인정보를 쓰지 마세요.
- 조회로는 **접수번호·처리 상태·유형·접수일·공개 처리 결과**만 보이고, 제보 내용·장소·이름·연락처·내부 메모는 절대 나가지 않습니다. 무작위 대입을 막기 위해 같은 접속지에서 1분에 30번까지만 조회됩니다.
- 한계: 접수번호를 아는 사람은 누구나 상태를 볼 수 있으므로 접수번호를 남에게 공유하지 마세요.

## 오늘의 안전·친환경 퀴즈 · 전체 검색 · 화면 설정
- **퀴즈**: 홈에서 매일 1문제가 나오고(날짜마다 고정, 모든 사람이 같은 문제), 정답·해설을 바로 볼 수 있습니다. "퀴즈 더 풀기"에서는 분야(안전/비상·응급/촬영현장/친환경)를 골라 5문제를 도전합니다. 문제 은행은 100문항(안전 30 · 비상 22 · 촬영 26 · 친환경 22)이며, `quiz-data.js` 에 같은 모양으로 한 줄을 더하면 문제가 늘어납니다. 정답률·연속 도전 일수는 사용하는 기기에만 저장됩니다.
- **전체 검색**: 화면 위쪽 🔍 버튼. 안전수칙·비상대응·친환경·촬영안전(장비와 공통 수칙) 본문을 한 번에 찾고, 결과를 누르면 해당 항목이 펼쳐진 채로 열립니다.
- **화면 설정**: 화면 위쪽 "가" 버튼. 글자 크기(표준/크게/아주 크게)와 고대비 모드를 켤 수 있고, 이 기기의 브라우저에 저장됩니다.

## 사진 30일 자동 정리 (저장 공간 보호)
접수 후 **30일이 지난 사진**을 매일 자동으로 지웁니다. 제보 글·처리 상태·조치 내용은 그대로 남고, 관리자 상세 화면에는 "보관기간(30일)이 지나 삭제되었습니다"가 표시됩니다. (무료 플랜 저장 공간 약 1GB가 사진으로 가득 차는 것을 막기 위한 장치입니다.)
- 방식: GitHub Actions(`.github/workflows/photo-cleanup.yml`)가 매일 새벽 관리자 계정으로 로그인해서 Supabase 저장소 API로 사진을 지웁니다. (SQL로 직접 지우면 파일이 남을 수 있어 이 방식을 씁니다. `service_role` 같은 만능 키는 쓰지 않습니다.)
- 설정 (한 번만): GitHub 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에 4개를 등록합니다.
  - `SUPABASE_URL`, `SUPABASE_ANON_KEY` (keep-alive에 쓰는 값과 같음)
  - `ADMIN_EMAIL` (관리자 이메일), `ADMIN_PASSWORD` (**서버 비밀번호 = 숫자 암호 + `-safety`**, 예: `12345678-safety`)
  - 권장: 사진 정리 전용 관리자 계정을 따로 만들어(Authentication → Users에서 새 사용자, `add_admin.sql`에서 그 이메일 실행) 그 계정을 쓰면 비밀번호 관리가 쉽습니다.
- 확인: **Actions** 탭 → "Photo cleanup (30 days)" → **Run workflow** → `dry_run` 체크(시험 실행: 지우지 않고 대상만 표시) → 초록색 체크와 "삭제 대상 N장" 로그를 확인한 뒤, 체크 없이 한 번 더 실행합니다. 이후 매일 자동 실행됩니다.
- 보관 일수는 워크플로 파일의 `RETENTION_DAYS: '30'` 을 바꾸면 됩니다. 이 정리를 쓰지 않으려면 시크릿을 등록하지 않으면 건너뜁니다.
- ⚠ GitHub는 오래 활동이 없는 저장소의 예약 실행을 멈출 수 있으니 가끔 Actions 탭을 확인하세요. 개인정보 처리방침의 사진 보관 기간도 30일로 맞춰 두세요.

## 친환경 (사무실 · 홍보물 · 행사)
- **친환경 화면**(홈 또는 바로가기에서 "친환경"): 친환경 실천 8가지, 내 자리 친환경 셀프체크(8개), 분야별 수칙 7개(에너지 절약 / 물 절약·탕비실 위생 / 종이·일회용품 줄이기 / 분리배출 / 폐기물 안전 / 친환경 이동·출장 / 친환경 홍보물·행사), 촬영현장 친환경 연결, 안전신문고 제안 버튼으로 구성됩니다. 예전에 안전수칙에 있던 "친환경·에너지 절약"과 "분리배출·폐기물 안전"은 이 화면으로 옮겨 내용을 보강했습니다. 내용은 `content.js` 의 `ECO_TOP`, `ECO_SELFCHECK`, `ECO` 에서 고칩니다.
- **촬영현장**: 촬영안전 → 공통 수칙의 "친환경 촬영" 카드(체크리스트 13개 + 상황별 안내 4개)와 전원·조명·드론 장비 페이지의 "친환경" 항목입니다. 내용은 `shoot-data.js` 의 `COMMON.eco`, `COMMON.ecoGuide` 에서 고칩니다.
- ⚠ 분리배출 기준·적정 실내온도(예: 여름 26℃ 이상, 겨울 20℃ 이하)·폐기 절차는 일반적인 안내 수준으로 쓴 것이므로, 기관 안전·시설 담당 부서의 확인을 받고 기관의 에너지 절약·탄소중립 지침이 있으면 그 문구로 바꿔 쓰세요.

## 촬영안전 탭 (촬영현장 안전가이드)
- 홈의 **촬영현장 안전가이드** 버튼, 또는 하단 **바로가기** → **촬영안전**으로 들어갑니다. 서버(Supabase) 설정 없이도 동작하는 화면입니다.
- **장비**: 카메라·드론·삼각대·조명·짐벌·지브/크레인·달리/슬라이더·오디오·전원/배터리 9종. 이름 검색, 분류 필터, 위험도 색상 표시가 있고, 장비마다 보호구 · 사용 전/중/후 수칙 · 환경별 추가 수칙 · 자주 하는 실수 · 절대 금지 · 사고 시 조치 · 점검 체크리스트 · 관련 기준이 나옵니다.
- **공통 수칙**: 촬영 전 5분 브리핑 체크리스트, 날씨·시간대별 대응, **친환경 촬영**(촬영 전·중·후 체크리스트와 배터리·세트 폐기물·야외 자연환경·연기 효과 안내), 응급처치 요약, 사고 발생 시 순서. 전원·조명·드론 장비 페이지에도 친환경 안내가 들어 있습니다.
- **점검 체크리스트**는 사용하는 휴대폰 브라우저에만 저장됩니다(서버로 전송되지 않음).
- **보고 문구 복사**: 사고·아차사고 내용을 적어 복사해 관리자에게 메시지로 보내는 기능이 있고, 같은 화면의 **안전신문고로 제보하기** 버튼으로 기록이 남는 제보로 바로 이어집니다. 안전신문고의 장소 목록에는 "촬영 현장 · 스튜디오"가 추가되어 있습니다.
- **QR 라벨**: 촬영안전 → 상단 "QR 라벨" 메뉴에서 장비별 QR 라벨(개별 이미지 / A4 한 장 12개 시트 / 바로 인쇄)을 만듭니다. 장비에 붙이고 스캔하면 `https://내계정.github.io/safety-site/#shoot/camera-01` 처럼 그 장비 페이지가 바로 열립니다. 사이트 주소를 먼저 저장해야 하고, QR 생성 라이브러리(cdnjs)를 인터넷에서 불러옵니다.
- **내용 수정**: 장비·수칙은 `shoot-data.js` 의 `EQUIP`(장비), `COMMON`(공통 수칙), `CATS`(분류), `PPE`(보호구 아이콘)만 고치면 됩니다. 장비를 추가하면 목록·검색·QR 라벨에 자동 반영됩니다. 장비 `id`는 QR 주소에 들어가므로, 이미 붙인 라벨이 있으면 바꾸지 마세요.
- 안전수칙 내용은 일반적인 안내이므로, 실제 현장 규정·제조사 매뉴얼·최신 법령과 다르면 그쪽을 우선한다는 안내 문구가 화면에 들어 있습니다. 법령 근거(`refs`)와 응급처치 수치는 기관 안전 담당자의 검토를 받아 사용하세요.

## 동작 확인 체크리스트 (꼭 해 보세요)
1. 사이트 주소 접속 → **안전신문고** 탭 → 사진 한 장 포함해 **시험 제보** 접수 (휴대폰에서 사진 촬영 포함)
2. 접수번호(`SF-…`)가 나오는지 확인
3. 하단 **바로가기** → 맨 아래 **관리자** 버튼 → 숫자 암호 입력 → 방금 제보와 **사진이 보이는지** 확인
4. 제보 상세 → **🖨 접수증 출력** → 인쇄 미리보기 확인
5. 시험 제보 **삭제**
6. 다른 브라우저(로그인 안 한 상태)에서 `admin.html` 을 열어 **암호 없이 목록이 안 보이는지** 확인
7. **안전신문고**에서 시험 제보를 접수한 뒤, 받은 접수번호로 **처리 결과 조회**가 되는지, 관리자에서 "처리 결과(공개)"를 쓴 뒤 조회에 보이는지 확인
8. 관리자 **📊 통계·보고서**와 **📅 이달 캠페인**이 열리는지, 월간 보고서 미리보기가 나오는지 확인
9. **바로가기 → 촬영안전** → 장비 하나 열기 → 점검 체크리스트 체크 후 새로고침해도 유지되는지, QR 라벨 화면에서 QR이 그려지는지 확인 (휴대폰 카메라로 스캔해 해당 장비 페이지가 열리는지까지)
10. GitHub **Actions → Photo cleanup (30 days) → Run workflow** (dry_run 체크)로 사진 정리가 오류 없이 도는지 확인

## 보안·운영 시 알아둘 점
- **읽기 차단은 서버(Supabase)에서 합니다.** 화면 코드에 암호나 비밀 키가 들어 있지 않습니다. 관리자 암호는 Supabase 계정 비밀번호로만 존재합니다.
- 제보 입력값은 형식·길이 검사가 서버에서 다시 이루어지고, 상태·메모·접수시각 위조는 거부/보정됩니다. 도배 방지로 **전체 시간당 200건**을 넘으면 접수가 잠시 제한됩니다.
- 사진은 **비공개 저장소**에 보관되고 관리자 로그인 후에만 볼 수 있습니다. 올리는 사진은 JPEG만, 장당 약 1.5MB 이하, 접수번호별 최대 3장입니다. 촬영 위치정보(GPS)는 화면에서 압축할 때 제거됩니다.
- **한계**: 로그인 없이 누구나 접수할 수 있는 구조라, 악의적으로 사진 파일만 대량 업로드하면 저장 공간(무료 플랜 약 1GB)을 일시적으로 소모시킬 수 있습니다. **사진 30일 자동 정리**가 매일 오래된 사진(제보 없이 올라온 사진 포함)을 지워 피해를 제한하지만, 하루 사이의 대량 업로드까지 막지는 못합니다. 문제가 생기면 Supabase 대시보드에서 직접 정리하세요.
- 사진 정리용 `ADMIN_PASSWORD` 시크릿은 GitHub Secrets에만 두고 코드·화면·로그에 쓰지 마세요. 정리 전용 관리자 계정을 따로 쓰면 비밀번호를 바꾸기 쉽습니다.
- 무료 플랜 한도(저장 용량·전송량·일시정지 정책)는 바뀔 수 있으니 Supabase 공식 요금 페이지에서 확인하세요.
- **개인정보**: 연락처는 선택 입력이며 동의가 있어야 저장됩니다. 서버 위치(서울 리전), 처리방침, 외부 클라우드 사용 가능 여부는 **기관 정보보안·개인정보 담당 부서 승인**을 받으세요.

## 문제 해결
| 증상 | 확인할 것 |
|---|---|
| 신문고에 "서버 연결 설정이 아직 되지 않았습니다" | 4단계 `site.config.js`의 URL/anon 키 입력 |
| 접수 시 "입력 내용을 다시 확인해 주세요" | 2단계 `schema.sql`을 실행했는지, 필수 항목 누락 여부 |
| 관리자 로그인이 계속 "암호가 올바르지 않습니다" | 3단계 비밀번호 = 숫자 암호 + `ADMIN_PIN_SUFFIX` 인지, 이메일 일치 여부 |
| "관리자 권한이 없는 계정입니다" | 3단계의 `add_admin.sql`을 실행했는지 |
| 관리자 화면에서 사진이 안 보임 | `schema.sql` 5)번 사진 저장소 설정이 적용됐는지 (재실행해도 안전) |
| 어느 날부터 접수가 안 됨 | Supabase 프로젝트 일시정지 여부 → 대시보드에서 Restore, 6단계 설정 |
| 접수번호 조회가 "아직 설정되지 않았습니다" | Supabase에서 `supabase/add_features.sql` 실행 여부 |
| 관리자 "저장하지 못했습니다 … reply" / "처리 결과 칸이 아직 없습니다" | `supabase/add_features.sql` 실행 여부 (실행 후 `notify pgrst, 'reload schema';`) |
| 이달 캠페인 화면에 "캠페인 저장소가 아직 없습니다" | `supabase/add_features.sql` 실행 여부 |
| "조회가 너무 많습니다" | 같은 접속지에서 1분에 30번을 넘었습니다. 잠시 뒤 다시 시도 |
| Actions의 Photo cleanup이 "로그인 실패" | `ADMIN_EMAIL`, `ADMIN_PASSWORD`(숫자 암호 + `-safety`) 시크릿 확인 |
| Photo cleanup "제보를 갱신할 권한이 없습니다" | 시크릿의 계정이 `add_admin.sql`로 관리자 등록되었는지, `add_features.sql` 실행 여부 |
| 글자 크기를 키웠는데 레이아웃이 어색함 | 오래된 브라우저는 확대를 지원하지 않을 수 있습니다. 최신 크롬·사파리·엣지를 쓰세요 |

## 검증 범위 (이 패키지를 만들면서 확인한 것 / 못한 것)
- 확인함: 데이터베이스 규칙(익명은 넣기만 가능·관리자만 조회/처리/삭제·위조 거부·도배 방지), 사진 저장소 규칙, 화면 전체 흐름(접수·관리자 로그인·처리·접수증·CSV·삭제)을 **Supabase를 흉내 낸 시험 환경**에서 검증했습니다.
- 촬영안전 탭은 시험 환경(가상 브라우저)에서 목록·검색·분류 필터·장비 상세·단계 탭·체크리스트 저장/복원·공통 수칙·보고 문구 복사·QR 라벨 생성과 기존 탭 이동이 오류 없이 동작하는 것까지 확인했습니다.
- 이번 기능 추가분은 다음과 같이 확인했습니다. **실제 PostgreSQL**에서 `schema.sql`과 `add_features.sql`을 두 번 실행해도 오류가 없고, 익명은 제보를 읽을 수 없으며 처리 결과·사진 삭제 표시를 위조할 수 없고, 접수번호 조회는 허용된 6개 항목만 돌려주며 같은 접속지에서 30번 뒤 제한되고, 캠페인은 관리자만 수정할 수 있음을 시험했습니다(Supabase를 흉내 낸 역할·함수 환경). 화면(검색·퀴즈·캠페인·챌린지·화면 설정·접수번호 조회)과 관리자 화면(통계·월간 보고서·처리 결과·캠페인)은 가상 브라우저와 가상 서버로, 사진 정리 프로그램은 가상 Supabase 서버로 시험했습니다.
- **확인하지 못함**: 실제 Supabase 저장소 API에서의 사진 목록·삭제 응답 형식(공식 문서를 기준으로 작성했으므로 Actions의 시험 실행으로 꼭 확인), 글자 크기 확대와 고대비의 실제 휴대폰 화면, 월간 보고서의 실제 인쇄 모양, QR 라벨의 실제 인쇄·스캔, 실제 Supabase 프로젝트와의 연결, GitHub Pages 실제 배포, GitHub Actions 실행, 휴대폰 카메라 촬영·사진 압축, 실제 프린터 출력. 위 "동작 확인 체크리스트"로 꼭 직접 확인해 주세요.
